# Консольный рогалик — спецификация дизайна

Дата: 2026-10-04

## 1. Цель и рамки

Небольшая консольная игра-рогалик, в которую приятно играть самому автору.

- Язык: C++20, сборка CMake, среда CLion.
- Зависимости: EnTT (ECS), Catch2 (тесты), оба через CMake `FetchContent` с закреплёнными версиями. Больше ничего.
- Платформы: Windows и POSIX. Платформенный код изолирован в `Terminal`.
- Язык интерфейса: английский. Все строки собраны в одном месте.
- Формат: классический рогалик. ASCII-карта, пошаговая ходьба по клеткам, бой при столкновении, перманентная смерть.
- Механики первой версии: этажи (5, на последнем босс), враги, инвентарь, оружие и броня, зелья, золото, уровни и опыт, туман войны.

Вне рамок первой версии: классы героя, магия, свитки, ловушки, голод, сохранение и загрузка, локализация, звук.

Критерий успеха: можно пройти забег от старта до победы над боссом или до смерти. Каждый забег отличается, потому что этажи генерируются. Забег воспроизводим по seed.

## 2. Структура проекта

```
CMakeLists.txt
src/
  main.cpp
  core/                   # логика без ввода-вывода
    components.hpp
    templates.{hpp,cpp}
    map.{hpp,cpp}
    generator.{hpp,cpp}
    systems/              # player, ai, movement, combat, death, progression, fov
    events.hpp
    rng.hpp
    game.{hpp,cpp}
  ui/
    terminal.{hpp,cpp}    # интерфейс + реализации Windows и POSIX
    renderer.{hpp,cpp}
    input.{hpp,cpp}
tests/
```

Границы:
- `core` ничего не знает о терминале. Получает `Command`, меняет мир.
- `ui` читает мир и рисует, но не меняет. Ввод превращается в `Command`.
- `Terminal` — единственное место с платформенным кодом: сырой ввод одной клавиши, очистка экрана, цвет, размер окна.
- Случайность идёт через один `Rng` с seed.

## 3. Компоненты, шаблоны, системы

Компоненты (простые структуры без логики):

| Группа | Компоненты |
|---|---|
| Мир | `Position{x,y}`, `Renderable{glyph,color}`, `Name`, `BlocksMovement` |
| Живые | `Health{cur,max}`, `Stats{attack,defense}`, `Level{lvl,xp}`, `XpReward{amount}` |
| Поведение | `Player` (тег), `AI{kind}` (блуждающий, преследующий, босс), `Faction` |
| Предметы | `Item`, `Consumable{effect,power}`, `Equippable{slot,atkBonus,defBonus}`, `Gold{amount}` |
| Владение | `Inventory{items}`, `Equipment{weapon,armor}`, `InInventory{owner}` |
| Карта | `Stairs`, `Viewshed{radius}` |

Туман войны хранится в `Map`: у клетки флаги `visible` и `explored`.

Шаблоны: таблица C++-структур в `templates.cpp` (id, glyph, характеристики, `minFloor`, `weight`). `spawn(registry, id, pos)` собирает сущность. Добавление врага или предмета — новая строка в таблице. Неизвестный id — `assert`.

Системы (функции над `entt::registry`), порядок за ход:
1. `playerCommand` — движение, подбор, использование и экипировка, спуск по лестнице.
2. `aiSystem` — BFS до игрока в радиусе зрения.
3. `movementSystem` — стена блокирует шаг, клетка с врагом превращается в атаку.
4. `combatSystem` — урон = max(1, attack − defense) плюс малый разброс из `Rng`. Промахов нет.
5. `deathSystem` — удаление мёртвых, XP, дроп. Смерть игрока завершает забег.
6. `progressionSystem` — повышение уровня.
7. `fovSystem` — shadowcasting, обновление `explored`.

События через `entt::dispatcher`: `Attacked`, `Died`, `ItemPickedUp`, `LevelUp`, `FloorChanged`. Журнал сообщений подписан на них.

Босс — обычный шаблон на 5-м этаже. Победа наступает при его убийстве.

## 4. Генерация этажа

Вход: `Rng`, номер этажа. Сетка 80×24.
1. Всё стены.
2. 6–9 прямоугольных комнат, перекрывающиеся отбрасываются.
3. Комнаты соединяются L-образными коридорами по порядку (i и i+1) — этаж связный.
4. Игрок в первой комнате, лестница вниз в последней. На 5-м этаже вместо лестницы стоит босс.
5. Остальные комнаты заполняются врагами и предметами по таблице шаблонов (`minFloor`, `weight`).

Если окно терминала меньше 80×24, игра показывает предупреждение.

## 5. Главный цикл и интерфейс

```
Game::run():
  startNewRun(seed)
  while state == Playing:
    renderer.draw(world)
    cmd = input.read()          // блокирующее чтение одной клавиши
    if cmd == Quit: break
    game.tick(cmd)              // не тратит ход, если действие невозможно
  показать экран победы или смерти
```

Состояния: `Playing`, `Inventory`, `Dead`, `Won`. `input` по текущему состоянию выбирает трактовку клавиш.

Управление: WASD или стрелки, `g` подобрать, `i` инвентарь, цифры — использовать предмет в меню, `e` экипировать, `>` спуститься, `q` выход.

Экран: первая строка — HUD (HP, Lv, XP, Floor, Gold), ниже карта, внизу последние 3–4 сообщения. Цвета из `Renderable`; без поддержки цвета игра монохромна.

## 6. Ошибки и надёжность

- `Terminal` восстанавливает исходный режим консоли через RAII, в том числе при исключении.
- Обычная игра не бросает исключений. Ошибки программиста ловятся `assert`.

## 7. Тесты

Catch2, тестируется только `core`:
- детерминированный урон при фиксированном seed;
- связность сгенерированного этажа (BFS от игрока до лестницы);
- подбор, использование и экипировка предмета;
- повышение уровня;
- смерть монстра и награда XP.

## 8. Принятые решения

- Бой без промахов, урон с малым разбросом.
- 5 этажей, босс на последнем.
- ECS через EnTT, шаблоны сущностей в виде таблиц в коде, без внешних файлов данных.
